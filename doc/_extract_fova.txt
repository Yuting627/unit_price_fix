Purpose of this document/ problem statement:
Purpose of the different tests included in the FoVa process is to assess at loading time the quality of incoming stores in regards to their structure and trend and provide early feedback on the quality of stores loaded to enable contacting the retailer in case received data suffers from issues like “identical data with previous week was sent”, “truncation”, “identical prices with previous week” and other well know reasons which can occur due to mismanagement of raw data from retailers side or for early identification of trend patterns which needs further explanations by the Retailer,
To derive to the above decision logic a set of statistical tests are run on loading time and when combined together they provide the data quality status of the store “ok” or “questionable” with the relevant reasoning and recommendations on actions.
The status of the store/week/ FoVa for each individual test (“questionable” or “ok”)  is govern by a set of parameters (upper and lower bound) which currently are static and are instructed/ update by the user in a specific FoVa table.
From the current experience it has been identified that the way we manage and update FoVa test parameters is creating inconsistencies on the final Store/FoVa status which in return generated a substantial number of “false questionable” stores which have to be manually inspected by the user and in return the final FoVa store status can be updated to reflect the result of this investigations.
In an effort to eliminate the number of “false questionable” stores and within the scope of the ZTV process we have analyzed and evaluate the current status and as a result a new approach for the definition of the FoVa test parameters has been defined.

Purpose of this document is to provide the specifications for the dynamic calculation and update of the parameters used in each FoVa test.

Process definition:
The objective of the Scan*Edit FOVA-function is to detect stores where the weekly scanning data file have some structural deficiency or structural changes. 
The detection of questionable data is based on a comparison of the current week data file with the one from the last good week. 
The objective is to make a statement about the general usability of the data (for a shop-period) and in particular to detect stores with structural deficiencies from one week to the other in terms of (we do not care about limited numbers of items with problematic data).
The structural deficiencies investigated through FOVA are the ones usually occurred:
Truncated file (in terms of completeness of the list of barcodes or number of days)
Identical file
Trend problems
Price problems
Other non-identified issues
FoVa works on the basis 3 types of indicators:
Structural indicators (Brackets of bar codes/ brackets of units sold / Price brackets ) 
Apart from some more diagnostic information the decision making whether a store is considered to have questionable data is taken based on comparisons of the frequency distributions of items according to:
Number of units sold
Structure of the item code
Price
The comparisons are done by means of a Kolmogorov-Smirnov test.

DYNAMIC CALCULATION OF FoVa test PARAMETERS 
Algorithm  description:
The analysis of the empirical data for each FoVa test results has indicated that the presence of strong seasonality from one week to the other requires a dynamic process for the evaluation of the FoVa test parameters (upper &amp; lower bounds) to recognise long tern variation (present in a number of weeks) but also in the short term (from one week to the other).
To recognise true outliers we are introducing a dynamic process where based on historical data:

We analyse for each FoVa test long term variation and define FoVa test parameters based on historical data of the past 13 weeks (longitude test)
We analyse for each FoVa test short term variation (difference of FoVa test results between 2 consecutive weeks and define FoVa test parameters based on this new variable (TREND TEST). 
As we cannot define parameters for the TREND TEST based on the current periods which would have been the identical process we perform this based on historical data of 13 weeks and as soon as an adequate number of stores are loaded in the current period we introduce a weighting process to combine knowledge from previous 13 and current week for the definition of the TREND TEST FoVa parameters.
For the final definition of FoVa Test parameters (upper and lower bound) the LONGITUTE and TREND test results are combined together to enable identification of the true questionable store
The FoVa  parameters defined through the  longitude test identify stores which are questionable because their overall FoVa test empirical values are above the upper and lower bound
The FoVa  parameters defined through the  TREND test identify stores which are questionable because of their change on the FoVa test empirical values between consecutive periods  are above the upper and lower bound defined based on historical data of period 13 weeks and the current week
A store/Week/Fova test takes a FINAL “questionable” status  if both test (longitude and TREND) are positive

Statistics calculation and definition of critical limits (FoVa test parameters)
For the evaluation and set up of the parameters’ default values it is suggested using the empirical distribution of the scores stored in the SirVal FoVa log files.

Evaluation of the empirical distributions: The evaluation of the empirical distributions of different parameters for different weeks, indicates different distribution shapes. 
The distributions of the parameter values appear as quite well behaved, but are somewhat more peaked and heavy-tailed then a  normal distribution.  A strong indication of skewness appears in most of the cases and this is different for the different statistics and is also different by week. Depending on the indicator the skewness could be positive or negative. 

Methodology description:
We will work with the empirical values of the different parameters for which the results are stored on a store/ weekly basis in SirVal.
WE USE THE DE-TRENDED EMPIRICAL VALUES AS DEFINED IN THE PREVIOUS STAGE
We will approach the evaluation of the parameters through the classical Tukey rule 
The process accounts also for the skewness observed in the distribution of the empirical parameter.
We take in consideration the period-to-period trend and store-level variation
Determine median IQR for centered deviance and setup a  0.7% symmetric boundary (0.7% corresponds with the 1.5*IQR which is typically used for outlier detection)
Add back in the max(abs(median)) on either side

The parameters definition is be based on prior 13 weeks 
Based on de-trended data as define in the previous step above
In the attached XL a demonstration of the method is described following the below steps:
Calculate by week Q1, median, Q3 and quartile skewness as (Q3-2*median+Q1)/(Q3-Q1)
Calculate by week IQR=Q3-Q1
Adjust by week Q1 and Q3 as:
If skewness &gt; 0 then adj Q1=Q1 and adj Q3=Q3*Q3/median
If skewness &lt; 0 then adj Q1=Q1*Q1/median and Q3=Q3
If skewness=0 then adj Q1=Q1 and adj Q3=Q3
Calculate by week adjusted IQR=adj Q3 – adj Q1
Calculate across all weeks Median(median), Max(IQR), Max(adj IQR) and MEDIAN(skewness)
Calculate ini LL and ini UL as LL=Median(median)-1.9992*Max(IQR) and UL=Median(median)+1.9992*Max(IQR)
Calculate final LL and final UL as:
If MEDIAN(skewness)&gt;0 then final LL=ini LL and final UL=Median(median)+1.9992*Max(adj IQR)
If MEDIAN(skewness)&lt;0 then final LL=Median(median)-1.9992*Max(adj IQR) and final UL=ini UL
If MEDIAN(skewness)=0 then final LL=ini LL and final UL=ini UL

FINAL LIMITS CALCULATION for the TREND test:

In current period scanning stores are received in batches (portions of 50-60 stores depending on the chain). Therefore the parameters limits calculation should be refreshed every time new stores enter in FoVa process to account for current period’s trend variation in the final parameters defined in the TREND process.

For combining the previous 13 weeks calculated parameters (short term calculation) with current week’s calculated parameters a weighting function is proposed to combine initial parameter values based on 13 previous periods only together with current weeks. 

This weighting function should grow when more stores are  received, must be equal to zero when no new stores are received and be maximized when all store data in tp is available. This maximum value (max_share_new) is also a free parameter, here set to 0,5 – so  weighting function produces an average of the initial MEDiqr of 13 previous periods (initial_median) and tp iqr median. 

A weighting function is also proposed as the function of number of stores received at the moment. This weighting function should grow when more stores are received, must be equal to zero when no new stores are received and be maximized when all store data in current period are available. The proposed weighting function is:

weight= tp_stores_receivedtp_stores_total*max⁡_share_new
 where maximum value (max_share_new) is also a free parameter, here set to 0.5, so when all stores are received, weight will be equal to 0.5 as default. 
The square root is taken because the variance decays as 1/sqrt(N), where N is a number of observations.

To get the final limits for current week, the limits based on last 13 periods (LLt1-13, ULt1-13) and limits based on current week (LLt, ULt) are combined with a weigh parameter (weight). The final limits for the current week t is 
LLtf = weight * LLt + (1 – weight) * LLt1-13 
ULtf = weight* ULt + (1 – weight) * ULt1-13

For testing, weight is set as 0.5 by default.

TREND TEST_317 – modified algorithm

Current approach of calculating TREND exceptions in FoVa (test 317) has been added recently to enable validation of TREND behavior of stores and use this as a tool to identify which of the stores classified as outliers (mainly unidentified reason)  are really classified as “questionable” stores.
The algorithm used for the trends test (TEST 317) takes last 8 weeks and calculates confidence interval assuming normality of the sales data. This approach is not adequate for the specific data given that scanning data is affected by strong seasonality over periods.
 
To enable better TREND validation a new approach is proposed which recognizes the trend variation over periods by looking at the difference between 2 consequtive weeks.

The new simple approach was proposed to evaluate the trend of units/value sold. This  method to derive each period TREND values  assumes n0 to be the number of units for last period, n1 – for current period. Thus 

TREND variable = (n1-n0) / ( (n1+n0) / 2 )

This criterion is inspired by considering period sales to be independent ‘quasi’ Poisson observations (stdev proportional to sort of expectation). According to this theory TREND values  should have a normal distribution around 0 with variance reflecting the proportionality constant.  The absolute value then has a half-normal distribution which also has a fixed mean/variance relationship (sqrt(pi/2-1)=0.755). The method was tested on real data to assess how they meet the assumption above.

METHODOLOGY for TREND_317 limits calculation

TREND values calculation
Assume n0 is the number of units for last good period, n1 – for current period. Then 
TREND_variableij = (nj-nj-1)/Avgn0n1 

Where 
i= store
j= week
Avgn0n1 = (n1+n0)/2 (average of the store items between the current and previous week)

TREND limits calculation
Limits are calculated each period separately for each IBD. “Sample” here means all TREND_variable  values at a particular period for particular IBD.
The approach is based on “adjusted” boxplot technique, which is sensitive to distribution skewness and differs from conventional boxplot approach by the different length of whiskers, which define the outliers in data.
To measure the skewness of a univariate sample {x1, . . . , xn} from a continuous unimodal distribution F, we use the medcouple (MC). It is defined as

MC = med h(xi , x j ) for all xi &lt;=Q2&lt;= xj with Q2 the sample median and where for all xi &lt;&gt; xj the kernel function h is given by

h(xi , xj) =((xj − Q2) − (Q2 − xi))/(xj – xi)(1)
Given the quartiles Q1, Q3, the interquartile range IQR = Q3-Q1, and the medcouple M, the “fence” is defined, for M ≥ 0 as
[Q1 - c*exp(a * MC)*IQR, Q3 + c*exp(b * MC)*IQR],(2)
and for M &lt; 0 as
[Q1 - c*exp(-b * MC)*IQR, Q3 + c*exp(-a * MC)*IQR],(3)
and all observations x outside the fence are the “potential outliers”. 
Here we assume 
a = -4, 
b = 3,
c = 7.

ALPHA PARAMETER USED IN KS TESTS

Structure indicators - KS parameters
The decision making whether a store is considered to have questionable data in regards to it’s structure  is mainly driven by the  comparisons of the frequency distributions of items according to:
Number of units sold
Structure of the item code
Price
The comparisons are done by means of a Kolmogorov-Smirnov test.

The KS-statistic in itself appears to be a good measure for structural changes in the data files. However, it seems that the textbook critical values for the Kolmogorov-Smirnov test are not very well adapted to our particular application. 
Part of the problem stems from the fact that some of the assumptions of the Kolmogorov-Smirnov test are not respected/appropriate in our situation:
Our ‘samples’ are not independent The KS critical values are however assuming both samples are independent. 
especially for the test on units-sold the null-hypothesis of the KS-test is not appropriate. The null-hypothesis of the classical KS-test is that the two distributions are equal (it means that the KS-test on units sold is detecting all cases where there is some trend between the two weeks) As we only want to consider a store questionable when the observed trend is very extreme thus we should be looking to reject a H0: ‘data change within reasonable limits’. 
It is because this inappropriateness of the traditional null-hypothesis for the unit sold test that the textbook critical values are much too restrictive. 

Determination of critical values for the KS-test:
The issue of the proper level of the critical values can be handled by falling back on the empirical distribution. 
We follow the same logic as the traditional hypothesis test but we may attempt to tune the model to make it more appropriate for our situation. 
In the traditional test the critical values are determined as percentiles on the theoretical distribution of D under the null-hypothesis of no-change. 
Rather then picking percentiles from the theoretical distribution, we could refer to the empirical distribution of the D’s we have observed historically in our sample.
 We could then consider only the distribution over the cases which we have not considered to be truly problematic (our new H0). 
Critical values will be selected as percentiles from this empirical distribution. In other words, we determine critical values according to what appears to be exceptional in our cumulated experience.

DEFINITION OF KPI’s
Purpose of the KPI system is to provide to the system operator sufficient information on the health of the process with statistics on the stores loaded and their status.
The process requires  an early indication of the quality of loaded data in order to react quickly and rectify possible issues occurred with scanning data .

As purpose of the FoVa process is to detect issues related with the correctness and completeness of reports data identifying specific issues like:
Truncated data,
Identical volumetrics
Identical prices
It is important to create a simple and complete KPI system which will provide statistics on the above elements and provide also sufficient information on the magnitude of the problem i.e. we will be taking different actions if we know that a chain has provided identical volumetrics data for all it’s stores or for a small number of stores.

Dimensions:
By IBD / chain

Statistics on loading process:
Stores loaded vs. expected
Questionable &amp; ok stores vs. loaded
Questionable stores by reasoning

Statistics for system health (success measure):
Number of outliers by test 
For historical parameters
For longitude parameters
Both (cross-section of both tests)
